1. Machine Learning เรียนรู้อะไร

ML เรียนรู้รูปแบบจากประสบการณ์ E เพื่อให้ทำงาน T ได้ดีขึ้นตามตัวชี้วัด P ตัวอย่างระบบกรองสแปม: T คือจำแนกอีเมล, E คืออีเมลที่มีป้ายกำกับในอดีต, P อาจเป็น precision/recall ตามต้นทุนความผิดพลาด ไม่ใช่แค่บอกว่า “ใช้ AI”

การเขียนโปรแกรมแบบดั้งเดิมป้อนข้อมูลและกฎเพื่อได้คำตอบ ส่วน supervised ML ป้อนข้อมูลและคำตอบเพื่อเรียนรู้โมเดล แล้วใช้โมเดลกับข้อมูลใหม่ กฎชัดเจน เช่น คิดภาษีตามอัตราที่กำหนด ไม่จำเป็นต้องแทนด้วย ML

Training: (X, y) → algorithm → fitted model | Inference: X_new → fitted model → ŷ

AI เป็นแนวคิดกว้าง; ML เป็นส่วนหนึ่งของ AI; Deep Learning ใช้ neural network หลายชั้น ส่วน Generative AI อธิบายความสามารถสร้างข้อมูลใหม่ โมเดล GenAI สมัยใหม่จำนวนมากใช้ DL แต่ไม่ควรนิยามว่า generative model ทุกชนิดต้องเป็น deep network

2. เลือกประเภทจาก target และ feedback

ประเภทสิ่งที่มี / เป้าหมายตัวอย่างและข้อสังเกต
SupervisedX และ y / ทำนายผลใหม่Regression: ค่าไฟ kWh; Classification: spam/ham แม้ class จะเขียนเป็นเลข 0/1 ก็ไม่ใช่ค่าต่อเนื่อง
UnsupervisedX ไม่มีคำตอบเป้าหมายClustering, ลดมิติด้วย PCA, ค้นหาความผิดปกติ ต้องตีความผลร่วมกับบริบท
Semi-supervisedข้อมูลติด label บางส่วนและไม่มี label จำนวนมากใช้โครงสร้างข้อมูลร่วมกับ labels; pseudo-label ที่ผิดอาจขยายความผิดพลาด
Reinforcementagent, state, action, rewardเรียนรู้นโยบายการตัดสินใจต่อเนื่องเพื่อผลตอบแทนสะสม ไม่ใช่มีเฉลยรายแถวเหมือน supervised

3. Workflow ที่ถูกต้องตั้งแต่ต้นจนจบ

  1. กำหนดผู้ใช้ การตัดสินใจ target หน่วย และเวลาที่ต้องทำนาย เช่น 20:00 วันนี้คาดการณ์ไฟฟ้าของวันพรุ่งนี้
  2. ระบุ features ที่รู้ได้ ณ เวลานั้น ตรวจ schema, missing, duplicate, identifier และข้อมูลคนเดิมหลายแถว
  3. กัน final test ตามเวลา/กลุ่ม/การสุ่มที่สอดคล้องการใช้งาน แล้วทำ EDA และออกแบบ features บน development/train
  4. ทำ preprocessing ภายใน Pipeline: impute → encode/scale → model; fit เฉพาะ train ของแต่ละ fold
  5. เทียบกับ baseline เช่นค่าเฉลี่ยหรือ majority class เลือก model และ hyperparameters จาก validation/CV
  6. ล็อกแบบแล้วประเมิน final test; สื่อสารข้อจำกัด ติดตาม drift และคุณภาพเมื่อใช้งานจริง

4. Bias–variance และ generalization

อาการการตีความการแก้ที่มีเหตุผล
Train error สูง + validation error สูงใกล้กันUnderfit / bias สูงเพิ่ม features ที่เกี่ยวข้อง เพิ่มความยืดหยุ่น ลด penalty ที่แรงเกินไป
Train error ต่ำ + validation error สูงOverfit / variance สูงลดความซับซ้อน เพิ่ม regularization เพิ่มข้อมูลที่เกี่ยวข้อง ใช้ bagging
Train และ validation ดีใกล้กันมีหลักฐาน generalization บน split นี้ตรวจ leakage และความสมจริงของ split ก่อนสรุป
Expected squared prediction error = Bias² + Variance + irreducible noise

Bias คือความคลาดเคลื่อนเชิงระบบของค่าเฉลี่ยคำทำนาย ส่วน variance คือความไวเมื่อเปลี่ยนชุดฝึก Noise ที่ลดไม่ได้เป็นความไม่แน่นอนของข้อมูลภายใต้ features ที่มี สูตรแยกข้างต้นอิง squared loss และสมมติฐานของการสร้างข้อมูล ไม่ใช่สูตรของ accuracy

ระวังในข้อสอบ

การเพิ่มข้อมูลช่วย high variance ได้บ่อย แต่ไม่แก้ high bias โดยอัตโนมัติ การเพิ่ม degree หรือลด k มักทำให้โมเดลยืดหยุ่นขึ้น แต่ผลแต่ละ seed ไม่จำเป็นต้องตรงภาพทฤษฎีทุกครั้ง

5. scikit-learn API ที่ต้องอ่านออก

APIหน้าที่สิ่งที่ห้ามสับสน
fit(X_train, y_train)เรียนรู้พารามิเตอร์ไม่เรียก fit กับ validation/test
transform(X)แปลงด้วยสถานะที่เรียนรู้แล้วscaler ใช้ mean/std ของ train เดิม
fit_transform(X_train)fit และแปลง trainหากทำกับข้อมูลทั้งหมดก่อน CV จะรั่ว
predict(X_new)ทำนาย label/ค่าต่อเนื่องinput features ต้องมีลำดับและรูปแบบเดิม
predict_proba(X)ความน่าจะเป็นตามลำดับ classes_ใช้ probability/score กับ ROC-AUC
score(X,y)metric ค่าเริ่มต้นของ estimatorLinearRegression = R²; classifier ทั่วไป = accuracy
get_params / set_paramsอ่าน/ตั้ง hyperparameterscoef_, intercept_ เป็นค่าหลัง fit

X มักมี shape (n_samples, n_features), y มี shape (n_samples,) ถ้ามี feature เดียวใช้ reshape(-1, 1) ไม่ส่งเวกเตอร์แบนแทน X

6. LLM, reproducibility และการอธิบายผล

LLM ช่วยเสนอ EDA ร่างโค้ด debug และเรียบเรียงรายงาน แต่ผู้ทำต้องตรวจสูตร คอลัมน์ ลำดับ split และรันจริง ไม่คัดลอกผลตัวเลขที่โมเดลภาษาแต่งขึ้น หลีกเลี่ยงข้อมูลส่วนบุคคลหรือข้อมูลลับ และเปิดเผยการใช้เครื่องมือตามกติกาวิชา

บันทึก random_state/seed, เวอร์ชันแพ็กเกจ, ข้อมูล, split และ metric Seed ช่วยทำซ้ำภายใต้สภาพแวดล้อมและลำดับการสุ่มเดิม ไม่ได้ทำให้ noise เป็นศูนย์หรือทำให้การทดลองมีคุณภาพโดยตัวมันเอง

ตอบจากความจำ

ทำนายเกรด A/B/C กับทำนาย GPAX ต่างกันอย่างไร?

A/B/C คือ classification; GPAX คือ regression เพราะต้องการค่าตัวเลขต่อเนื่อง แม้ใช้ features ชุดเดียวกันได้

ทำไม validation ที่ดีจึงยังไม่รับประกันระบบจริง?

อาจมี leakage, distribution shift, ตัวอย่างไม่เป็นตัวแทน หรือกระบวนการทำนายจริงไม่มี feature บางตัว ต้องตรวจโจทย์และเวลาใช้งานด้วย
