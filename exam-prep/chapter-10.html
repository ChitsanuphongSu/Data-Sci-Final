10 · Ensemble Methods

รวมโมเดลให้เกิดประโยชน์ด้วยความหลากหลายของข้อผิดพลาด

หน้ารวม
1. ทำไมหลายโมเดลอาจดีกว่าโมเดลเดียว2. Bagging, Boosting และ Stacking3. Random Forest ทีละขั้น4. Gradient Boosting5. Feature importance และการสื่อสารตอบจากความจำ

1. ทำไมหลายโมเดลอาจดีกว่าโมเดลเดียว

การเฉลี่ยหรือโหวตช่วยเมื่อโมเดลมีข้อมูลที่มีประโยชน์และไม่ผิดเหมือนกันทั้งหมด Diversity สำคัญพอ ๆ กับจำนวนโมเดล ถ้าทุกต้นใช้กฎเดียวกันและผิดจุดเดียวกัน การเพิ่มจำนวนไม่ได้สร้างข้อมูลใหม่

เสริมความเข้าใจ: Var(mean of B models)=ρσ²+(1−ρ)σ²/B

สูตรนี้สมมติ variance เท่ากันและ pairwise correlation เท่ากับ ρ แสดงว่าจำนวนต้นช่วยลดส่วนที่ไม่สัมพันธ์กัน แต่ถ้า ρ สูงจะมีเพดานประโยชน์ Ensemble ไม่รับประกันว่าจะชนะทุก dataset

2. Bagging, Boosting และ Stacking

วิธีการฝึกวิธีรวม / จุดเน้น
Baggingสุ่มตัวอย่างแบบใส่คืน ฝึกโมเดลแยกกันเฉลี่ย/โหวต ลด variance โดยเฉพาะ base learner ที่แกว่ง
Boostingฝึกตามลำดับให้แก้ข้อผิดพลาดของ ensemble ก่อนหน้ารวมแบบ additive; ลด bias ได้ แต่ overfit ได้
Stackingหลาย base models สร้าง prediction เป็น featuresmeta-model เรียนรู้วิธีรวม ต้องใช้ out-of-fold predictions สำหรับฝึก meta-model
ระวังในข้อสอบ

ถ้าใช้ prediction ของ base model บนแถวที่มันเคย train เพื่อสอน meta-model จะให้ภาพง่ายเกินจริง Stacking ต้องออกแบบ CV และกลุ่ม/เวลาให้เหมาะด้วย

3. Random Forest ทีละขั้น

  1. สุ่ม n แถวแบบใส่คืนจาก train เพื่อสร้าง bootstrap dataset ต่อต้น
  2. ทุก node สุ่มเพียง subset ของ features ให้แข่งขันหา split
  3. สร้างต้นไม้หลายต้นอย่างเป็นอิสระภายใต้พารามิเตอร์ควบคุม
  4. Regression เฉลี่ยค่าทำนาย; classification ของ sklearn เฉลี่ย probability ของต้นไม้แล้วเลือก class ที่มี probability สูงสุด

ใน bootstrap n ครั้ง มีแถวต้นฉบับที่ไม่ถูกเลือกประมาณ (1−1/n)ⁿ≈36.8% เมื่อ n ใหญ่ เรียก out-of-bag (OOB); แถวที่ปรากฏอย่างน้อยหนึ่งครั้งประมาณ 63.2% ไม่ใช่บอกว่าขนาดชุด bootstrap มีเพียง 33%

Hyperparameterเพิ่ม/ลดแล้วเกิดอะไร
n_estimatorsเพิ่มมักทำให้ค่าเฉลี่ยเสถียรขึ้นแต่ใช้เวลามากขึ้น ผลดีอาจอิ่มตัว
max_depthลดเพื่อจำกัดความซับซ้อนของแต่ละต้น
min_samples_leafเพิ่มเพื่อให้ใบใหญ่ขึ้นและลดการ fit noise
max_featuresลดเพื่อเพิ่มความหลากหลายระหว่างต้น แต่อาจทำให้แต่ละต้นอ่อนลง
n_jobsกำหนดการใช้ CPU; −1 ใช้ cores ที่พร้อมใช้งาน

RF ยัง overfit ได้ การเพิ่มจำนวนต้นอย่างเดียวไม่ใช่ยาแก้ทุกกรณี OOB ช่วยประเมินภายในข้อมูลฝึกที่เหมาะกับการสุ่มอิสระ แต่ไม่ทดแทน temporal/group validation เมื่อการใช้งานมีโครงสร้างนั้น

4. Gradient Boosting

Fₘ(x)=Fₘ₋₁(x)+ηhₘ(x)

เริ่มด้วย predictor ง่าย ๆ เช่นค่าเฉลี่ย y สำหรับ squared error จากนั้นคำนวณ residual y−F แล้วฝึกต้นตื้นทำนาย residual อัปเดตด้วย learning rate η แล้วทำซ้ำ สำหรับ loss อื่นใช้ negative gradient ของ loss ไม่ใช่ residual y−ŷ แบบเดียวเสมอ

ตัวอย่าง F₀=10, y=14, residual=4; ถ้าต้นใหม่ทำนาย correction=3 และ η=.1 จะได้ F₁=10.3 ไม่ใช่ 13 การใช้ η เล็กมักต้องเพิ่มจำนวนรอบ แต่ไม่ได้รับประกันว่าดีกว่าเสมอ

การควบคุมเหตุผล
learning_rate + n_estimatorsพิจารณาร่วมกัน: ก้าวเล็กแต่หลายรอบ
max_depth / leavesจำกัด complexity ของ weak learners
subsample / feature samplingเพิ่ม stochasticity และช่วย regularize
Early stoppingหยุดเมื่อ validation metric ไม่ดีขึ้นตาม patience; ห้ามใช้ final test หยุดฝึก

บทเรียนกล่าวถึง XGBoost (regularization และระบบฝึกประสิทธิภาพสูง), LightGBM (histogram-based, leaf-wise growth) และ CatBoost (จัดการ categorical features เด่น) แต่ไม่มีไลบรารีใดชนะเสมอ โค้ดฝึกในเว็บใช้ GradientBoostingClassifier ของ sklearn เพื่อลด dependency

5. Feature importance และการสื่อสาร

Impurity-based importance สรุปการลด impurity จาก splits ใช้ดูว่าโมเดลพึ่ง feature ใด แต่เอนเอียงไปยังตัวแปรที่มีจุดแบ่งมากได้ และ correlated features แบ่งความสำคัญกัน Permutation importance ดูคะแนนลดลงเมื่อสลับ feature บนชุดประเมิน; หากใช้เพื่อเลือก features ชุดนั้นถือเป็น validation

ระวังในข้อสอบ

Importance สูงไม่บอกทิศทางและไม่พิสูจน์เหตุและผล Feature ที่มีข้อมูลอนาคตอาจสำคัญมากเพราะ leakage ต้องตรวจว่ารู้ได้เมื่อใด ไม่ใช่เชื่อคะแนนอย่างเดียว

  1. Problem: ใครใช้คำทำนายตัดสินใจอะไร
  2. Findings: metric บนข้อมูลที่ไม่ใช้ฝึก พร้อม baseline และลักษณะ error
  3. Confidence: ความแปรปรวนของ CV ขอบเขตข้อมูล และข้อจำกัด
  4. Recommendations: การทดลองหรือการตัดสินใจที่ทำได้จริง พร้อมติดตามผล

ตอบจากความจำ

Tree train 100%, validation 65% จะลองอะไร?

จำกัด depth/เพิ่ม min_samples_leaf, ตรวจ split และ leakage, ทดลอง RF พร้อม CV บนชุดเดิม ไม่เลือกด้วย test

RF กับ boosting ต่างกันที่ “ทำหลายต้น” อย่างเดียวหรือไม่?

ไม่ใช่ RF ฝึกต้นแยกกันด้วยข้อมูลและ features ที่สุ่ม ส่วน boosting สร้างต้นต่อเนื่องตามข้อผิดพลาดของ ensemble ปัจจุบัน
