บท 07 • LO1–LO2

เลือกชนิดการเรียนรู้จาก “สิ่งที่มี” และ “สิ่งที่ต้องการ”

Machine Learning เป็นส่วนหนึ่งของ AI ที่เรียนรู้รูปแบบจากข้อมูล การได้ข้อมูลมากขึ้นไม่ได้รับประกันว่าโมเดลจะดีขึ้น หากข้อมูลผิดหรือไม่ตรงกับงาน

วิธี ข้อมูลที่ใช้เรียนรู้ ตัวอย่างงาน
Supervised
มีคำตอบเป้าหมาย		 X คือข้อมูลนำเข้า และ y คือคำตอบในอดีต ทำนายเวลาส่งพัสดุจากข้อมูลการส่งที่มีเวลาจริง
Unsupervised
ค้นหาโครงสร้าง		 ไม่มี label เป้าหมายสำหรับงานนั้น แบ่งกลุ่มรูปแบบการซื้อ เพื่อสำรวจลักษณะลูกค้า
Reinforcement
เรียนรู้จากผลของการกระทำ		 สถานะ การกระทำ และรางวัลที่สะสมตามเวลา ฝึกตัวแทนจัดเส้นทางในระบบจำลองจากรางวัลและต้นทุน

Regression กับ Classification ต่างกันที่เป้าหมาย

“ส่งถึงในกี่นาที?” เป็น Regression เพราะต้องการปริมาณตัวเลข ส่วน “จะส่งทันหรือไม่?” เป็น Classification เพราะต้องการประเภท แม้ใช้ข้อมูลนำเข้าชุดเดียวกัน ก็เป็นคนละงานได้

ตัวเลขที่เป็นรหัส เช่น ประเภทสินค้า 1, 2, 3 ไม่ได้ทำให้งานนั้นกลายเป็น Regression ส่วนจำนวนสินค้าเป็นตัวเลขเชิงปริมาณ แม้เป็นจำนวนเต็ม ก็อาจใช้แบบจำลองถดถอยหรือโมเดลสำหรับข้อมูลนับ โดยตรวจว่าค่าพยากรณ์เหมาะกับงานหรือไม่

กฎที่แน่นอนอาจไม่ต้องใช้ ML

ถ้าค่าส่งกำหนดด้วยสูตรน้ำหนักและระยะทางที่แน่นอน ให้คำนวณตามกฎ แต่ถ้าต้องประมาณเวลาส่งที่มีการจราจร สภาพอากาศ และความไม่แน่นอน ML อาจช่วยเรียนรู้จากประวัติได้

บท 07 • LO3

การแบ่งข้อมูลคือการซ้อมสถานการณ์ใช้งานจริง

ก่อนฝึกโมเดล ให้กำหนดเป้าหมาย หน่วยของความผิดพลาด และเวลาที่ข้อมูลแต่ละตัวจะพร้อมใช้งาน

  1. กำหนดปัญหา: พยากรณ์ยอดสั่งอาหารของวันพรุ่งนี้ เพื่อวางแผนวัตถุดิบ
  2. สำรวจและแบ่งข้อมูล: ตรวจค่าหาย แถวซ้ำ หน่วย และแยกชุดข้อมูลให้ตรงกับเวลาใช้งาน
  3. สร้าง baseline: เช่น ใช้ค่าเฉลี่ยจากชุดฝึก เพื่อดูว่าโมเดลใหม่ช่วยได้จริงแค่ไหน
  4. ฝึกด้วย training: เรียนรู้ coefficients รวมถึงค่าเติมข้อมูลและค่าปรับสเกลจากชุดฝึกเท่านั้น
  5. เลือกด้วย validation: เปรียบเทียบ features, degree หรือ alpha ภายใต้เกณฑ์เดียวกัน
  6. ประเมินด้วย test: เมื่อเลือกวิธีแล้วจึงใช้ชุดที่กันไว้รายงานผลครั้งสุดท้าย ก่อนติดตามผลหลังใช้งาน
Trainingเรียนรู้พารามิเตอร์
Validation / CVเลือกวิธีและความซับซ้อน
Testตรวจผลหลังตัดสินใจ

หลีกเลี่ยง Data Leakage

ถ้าจะพยากรณ์ยอดของวันพรุ่งนี้ ห้ามใช้ “ยอดเงินจริงที่ปิดร้านพรุ่งนี้” เป็น feature เพราะยังไม่รู้ในเวลาพยากรณ์ ข้อมูลอากาศควรเป็นพยากรณ์อากาศที่มี ณ เวลานั้น ไม่ใช่อากาศจริงที่ทราบภายหลัง

ข้อมูลตามเวลาให้ฝึกจากอดีตและทดสอบกับช่วงถัดไป ส่วนข้อมูลหลายแถวต่อคนหรือร้าน ต้องระวังหน่วยเดียวกันปะปนข้ามชุด แบ่งแบบสุ่มได้เมื่อสอดคล้องกับสมมติฐานการใช้งาน

คำว่า test ในตัวอย่างเพื่อเรียน

หากเปิดดู error แล้วใช้ผลนั้นเลือก degree ซ้ำ ๆ ชุดนั้นกำลังทำหน้าที่เป็น validation แล้ว ควรมี final test อีกชุดที่ไม่ใช้ตัดสินใจ

บท 07 • LO4

เรียนรู้น้อยไป หรือจำข้อมูลฝึกมากไป?

Bias และ variance อธิบายความผิดพลาดจากคนละมุม ไม่ใช่ชื่อเรียก training error และ test error โดยตรง

Bias • คลาดเคลื่อนอย่างเป็นระบบ

ลองฝึกวิธีเดิมจากข้อมูลหลายชุด แล้วเฉลี่ยคำทำนาย ณ x เดิม ถ้าค่าเฉลี่ยยังห่างจากความสัมพันธ์จริง แสดงว่ามี bias ตัวอย่างเช่น ใช้เส้นตรงอธิบายแนวโน้มโค้งมาก ๆ

Variance • ไวต่อชุดฝึก

ใช้วิธีเดิมแต่เปลี่ยนชุดฝึก ถ้าคำทำนาย ณ x เดิมเปลี่ยนมาก แสดงว่ามี variance สูง ไม่ใช่เพียงข้อมูล y กระจายกว้าง

Expected squared prediction error = Bias² + Variance + Noise

แนวคิดสำหรับ squared loss ภายใต้ y = f(x) + noise ที่มีค่าเฉลี่ยศูนย์ และการเฉลี่ยเหนือชุดฝึก/ข้อมูลใหม่ Noise ที่ลดไม่ได้หมายถึงภายใต้ข้อมูลและกรอบปัญหาที่มีอยู่ ไม่ได้แปลว่าเก็บ feature เพิ่มแล้วจะช่วยไม่ได้เสมอ

สิ่งที่สังเกต ข้อสงสัย ลองตรวจหรือแก้
Train และ validation error สูงเทียบ baseline/เกณฑ์งาน อาจ underfit ตรวจข้อมูล เพิ่ม feature ที่เกี่ยวข้อง หรือเพิ่มความยืดหยุ่น
Train ต่ำ แต่ validation สูงกว่ามาก อาจ overfit ลดความซับซ้อน ใช้ regularization หรือเพิ่มข้อมูลที่ตรงงาน
ทั้งสองต่ำและใกล้กัน เป็นสัญญาณที่ดี ยังต้องตรวจ leakage และ final test

ช่องว่าง error เป็นสัญญาณให้ตรวจ ไม่ใช่หลักฐานพิสูจน์ bias/variance จากการแบ่งข้อมูลเพียงครั้งเดียว กราฟรูปตัว U เป็นภาพอธิบายที่พบบ่อย ไม่ใช่กฎว่าทุกโมเดลและทุกชุดข้อมูลต้องเป็นรูปนี้

ทดลอง • การเรียนรู้จากข้อมูลจำลอง

เปลี่ยน degree แล้วดูทั้งเส้นและความผิดพลาด

แบบทดลองนี้ fit polynomial จริงกับข้อมูลจำลอง 24 จุด และคำนวณ MSE กับ validation 80 จุดที่คงเดิม ข้อมูลใช้หน่วยสมมติ

วงกลม = ข้อมูลฝึก • เส้นทึบ = โมเดล • เส้นประ = ความสัมพันธ์จริงที่รู้ได้เพราะเป็นข้อมูลจำลอง กราฟตรึงแกน y ที่ −3 ถึง 3; ค่าที่เกินขอบไม่แสดงในกราฟ แต่รวมใน MSE ทั้งหมด

บท 08 • LO1

Linear Regression: อ่านเส้นให้เป็นความหมาย

โมเดลเส้นตรงใช้ค่าฐานและผลรวมของ features เพื่อประมาณตัวเลขเป้าหมาย

ŷ = b₀ + b₁x    หรือ    ŷ = b₀ + b₁x₁ + b₂x₂ + …

ŷ คือค่าพยากรณ์ b₀ คือ intercept และ b₁ คือ slope หรือ coefficient ของ x วิธี Ordinary Least Squares (OLS) เลือก coefficients ให้ผลรวม residual ยกกำลังสองในชุดฝึกต่ำที่สุด ภายใต้รูปแบบโมเดลที่กำหนด

ตัวอย่างจำลอง: เวลาส่ง (นาที) = 10 + 2 × ระยะทาง (กม.) ระยะ 5 กม. ได้คำทำนาย 20 นาที ความชัน 2 หมายถึงเมื่อระยะเพิ่ม 1 กม. ค่าพยากรณ์เพิ่ม 2 นาที ส่วนค่าฐาน 10 คือค่าที่โมเดลให้เมื่อระยะเป็นศูนย์ ซึ่งอาจอยู่นอกขอบเขตที่ข้อมูลรองรับ

จุด = เวลาจริงจำลอง • เส้นทึบ = ค่าพยากรณ์ • เส้นตั้งประ = residual หรือ y − ŷ ค่าบวกหมายถึงโมเดลทำนายต่ำกว่าค่าจริง แกนตั้งขยายเมื่อเส้นสูงเกินช่วงเริ่มต้น

ดูข้อมูลจำลองและ residual ของเส้นปัจจุบัน

ลองเลื่อนเส้นเพื่อให้ความผิดพลาดเล็กลง แล้วกด “ใช้เส้น OLS” เพื่อเปรียบเทียบ การผ่านทุกจุดไม่ใช่เป้าหมายเมื่อข้อมูลมี noise

บท 08 • LO3

เลือกตัวชี้วัดให้ตรงกับต้นทุนของการทำนายผิด

รายงานคะแนนพร้อมหน่วย ชุดข้อมูลที่ใช้ และ baseline เสมอ ค่าเดียวไม่เล่าทุกด้านของโมเดล

ตัวชี้วัด คำนวณจาก residual e = y − ŷ ความหมาย
MAE ค่าเฉลี่ย |e| พลาดสัมบูรณ์โดยเฉลี่ย หน่วยเดียวกับ y
MSE ค่าเฉลี่ย e² เน้นข้อผิดพลาดใหญ่ หน่วยของ y ยกกำลังสอง
RMSE √MSE เน้นข้อผิดพลาดใหญ่ แต่กลับมาใช้หน่วยเดียวกับ y
R² 1 − Σ(y − ŷ)² / Σ(y − ȳ)² เทียบกับการใช้ค่าเฉลี่ย y ของชุดที่ประเมิน ไม่มีหน่วย

ตัวอย่างคำนวณครบหนึ่งชุด

เวลาจริง = [10, 20, 30] นาที; ค่าพยากรณ์ = [12, 18, 26] นาที

residual = [−2, 2, 4] → |e| รวม 8 → e² รวม 24

2.67MAE • นาที
8.00MSE • นาที²
2.83RMSE • นาที
0.88R² • ไม่มีหน่วย

R² = 1 − 24/200 = 0.88 ไม่ได้หมายความว่า “ทำนายถูก 88%” และ R² อาจติดลบเมื่อพลาดมากกว่าการใช้ค่าเฉลี่ยของชุดประเมิน หาก y คงที่ ตัวหารเป็นศูนย์ ต้องตรวจวิธีจัดการของซอฟต์แวร์

“ในข้อมูลวันถัดมาที่กันไว้ โมเดลพลาดเฉลี่ย 2.67 นาที และ RMSE 2.83 นาที” ชัดกว่าพูดว่า “โมเดลดีมาก” หากพลาดช้าเกินกำหนดแพงกว่าพลาดเร็ว ควรตรวจความผิดพลาดสองทิศทางแยกกัน เพราะ MAE/RMSE ให้โทษตามขนาด ไม่แยกต้นทุนของทิศทาง

การเทียบ R² กับค่าเฉลี่ยของชุดประเมินเป็นนิยามของ metric ส่วน baseline ที่ใช้พยากรณ์จริงต้องเรียนค่าจาก training เท่านั้น

fit → predict → ประเมินผล: รู้ว่าข้อมูลไปที่ไหน

ตัวอย่างนี้สมมติว่าตารางแบ่งตามเวลาไว้แล้ว ทุก feature พร้อมใช้งาน ณ เวลาพยากรณ์ และไม่มีค่าหาย 

from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_absolute_error, mean_squared_error

# ตาราง train, validation, test แยกไว้ก่อนแล้ว
features = ["distance_km", "orders_in_queue"]
X_train = train[features]          # ตารางสองมิติ
y_train = train["delivery_min"]   # คำตอบเป้าหมาย

model = LinearRegression()
model.fit(X_train, y_train)       # เรียน coefficients
pred = model.predict(validation[features])
mae = mean_absolute_error(validation["delivery_min"], pred)
rmse = mean_squared_error(validation["delivery_min"], pred) ** 0.5
r2 = model.score(validation[features], validation["delivery_min"])
print(mae, rmse, r2)

fit เรียนรู้จากข้อมูลฝึก predict คืนคำทำนาย score คืนคะแนนตามชนิด estimator: สำหรับ LinearRegression คือ R² ไม่ใช่ accuracy เหมือนกันทุกโมเดล

Simple กับ Multiple

ใช้เพียง ["distance_km"] เป็น Simple Linear Regression ใช้ระยะทางและคิวงานร่วมกันเป็น Multiple Linear Regression ให้ประเมินบนชุดเดียวกันเพื่อเทียบอย่างยุติธรรม

หากสมการคือ ŷ = 8 + 2×ระยะทาง + 1.5×คิวงาน coefficient ของระยะทางหมายถึงค่าพยากรณ์เพิ่ม 2 นาทีต่อ 1 กม. เมื่อ features อื่นคงเดิม ความสัมพันธ์นี้ยังไม่พิสูจน์เหตุและผล และห้ามเทียบขนาด coefficient ข้ามหน่วยอย่างตรง ๆ เพื่อจัดอันดับความสำคัญ

Polynomial เช่น x และ x² ยังเป็นโมเดลเชิงเส้นใน coefficients แม้เส้นพยากรณ์จะโค้ง การเพิ่ม degree ทำให้ยืดหยุ่นขึ้นและอาจ overfit ได้

เมื่อเรากำหนดสมการสร้างข้อมูลเอง จะตรวจได้ว่าการ fit กู้ความสัมพันธ์กลับมาได้ใกล้เคียงเพียงใด โดยไม่คาดหวังว่าตัวอย่างที่มี noise ต้องได้ coefficient ตรงเป๊ะ

y = ax + b + ε   โดย ε มีค่าเฉลี่ย 0
import numpy as np
rng = np.random.default_rng(123)
x = rng.uniform(0, 10, size=50)
noise = rng.normal(loc=0, scale=1, size=50)
y = 2 * x - 3 + noise       # ความชัน 2; intercept -3
X = x.reshape(-1, 1)         # 50 แถว, 1 feature

สัญญาณ 2x − 3 เขียนในรูป ax + b ได้โดย a = 2 และ b = −3 ถ้าเปลี่ยนค่าเฉลี่ย noise เป็น 0.5 ค่าเฉลี่ยของ y เมื่อรู้ x จะเป็น 2x − 2.5 จึงต้องแยก “ค่าฐานในโค้ด” ออกจาก “ค่าฐานของความสัมพันธ์เฉลี่ย”

Seed ทำให้สร้างลำดับสุ่มซ้ำได้เมื่อใช้ generator วิธีและลำดับคำสั่งเดิม ไม่ทำให้ข้อมูลไร้ noise หรือทำให้โมเดลแม่นขึ้น อย่าเขียน np.random.seed = 123 เพราะเป็นการเขียนทับชื่อฟังก์ชัน ใช้ generator ในตัวอย่างข้างบนแทน

Cost function: ให้คะแนนเส้นแต่ละเส้น

SSE = Σ(y − ŷ)² เป็นผลรวม ส่วน MSE = SSE/n เป็นค่าเฉลี่ย บนข้อมูลชุดเดียวกันที่ n คงที่และยังไม่มี penalty ทั้งสองเลือกเส้นที่ดีที่สุดตรงกัน แต่เมื่อนำ penalty มารวม ต้องระบุการหารด้วย n ด้วย เพราะทำให้ความหมายของ alpha ต่างกัน

ลองใช้กราฟเส้นตรงในบทก่อนหน้า: การเลื่อน slope/intercept คือการเดินบนพื้นผิว cost ในแกนพารามิเตอร์ สำหรับ OLS ที่กำหนด features คงที่ พื้นผิว squared-error เป็น convex ค่าต่ำสุดเฉพาะที่จึงเป็นค่าต่ำสุดโดยรวม แต่คำตอบอาจไม่เป็นเอกลักษณ์ถ้า design matrix มีคอลัมน์ที่พึ่งพากัน

Basis function คือฟังก์ชันที่ใช้สร้าง features ใหม่จาก x เดิม จากนั้น Linear Regression เรียนรู้น้ำหนักของแต่ละ feature

Polynomial basis

เปลี่ยน x เป็น [x, x², x³] เช่น x = 2 ได้ [2, 4, 8] ใช้ PolynomialFeatures(3, include_bias=False) แล้วให้โมเดลมี intercept ของตนเอง

Gaussian basis

แต่ละ feature ให้ค่าสูงเมื่อ x ใกล้จุดศูนย์กลาง cⱼ และลดลงเมื่อห่างออกไป ความกว้าง σ ควบคุมการลดลงนี้ ค่า feature ไม่ใช่ความน่าจะเป็น

φⱼ(x) = exp[−½((x − cⱼ)/σ)²]
ŷ = b₀ + b₁φ₁(x) + … + bₙφₙ(x)

เมื่อ centers และ widths ถูกกำหนดไว้ โมเดลยังเป็นเชิงเส้นใน coefficients แม้ไม่เป็นเส้นตรงใน x ตารางเดิมมีรูปร่าง (จำนวนแถว, 1) หลังแปลงด้วย N Gaussian bases จะเป็น (จำนวนแถว, N)

เส้นทึบสีเขียว = basis ที่ center 5 • เส้นประสีเทา = bases อื่น แต่ละเส้นเป็น feature หนึ่งคอลัมน์ ยังไม่ใช่เส้นพยากรณ์ที่ผ่านการ fit ข้อมูล

ดูตาราง features ที่ x = 0, 5, 10

ในคลาสของ Notebook: σ = width_factor × ระยะห่างระหว่าง centers ไม่ใช่ σ = width_factor โดยตรง แบบทดลองนี้วาง centers บนช่วงจำลอง 0–10 ถ้า N = 5 ระยะห่าง 2.5 และ factor = 0.5 จะได้ σ = 1.25 เมื่อเปลี่ยน N โดยคง factor ไว้ ความกว้างจริงก็เปลี่ยนด้วย

ลำดับการทดลองที่อ่านเหตุผลได้

  1. แบ่ง training/validation/test แล้วตรึงการแบ่งเดิมสำหรับทุกวิธี
  2. เลือกจำนวน basis, centers และ widths ชุดเดียวกัน เรียนส่วนที่ต้อง fit จาก training เท่านั้น

  4. เปรียบเทียบ OLS, Ridge และ Lasso บน validation เดิม ปรับ alpha ภายในแต่ละวิธี ไม่ใช้เลข alpha เท่ากันเป็นหลักฐานว่า penalty แรงเท่ากัน
  5. บันทึกทั้ง error และ coefficients แล้วประเมิน final test หลังเลือกวิธีแล้ว
