P02 · ทดลอง Bias–Variance (4 คะแนน)

ใช้ข้อมูลจำลอง y = sin(x) + noise (noise ปกติ ส่วนเบี่ยงเบนมาตรฐาน 0.25) ตาม protocol ใน starter_lab.ipynb (ถ้าใช้ notebook เดิม ให้ปรับให้ตรง protocol นี้: x กระจายสม่ำเสมอในช่วง 0–6, train 35 จุด, validation 200 จุดด้วย seed 2026 คงที่) ทดลอง polynomial degree 1, 3, 12 ด้วยข้อมูลฝึกจำนวนเท่ากัน และประเมินบน validation เดียวกัน ทำซ้ำด้วย seed 11, 22, 33 รายงาน train/validation RMSE และค่าทำนายที่ x = 2.0 ของแต่ละ degree ในแต่ละรอบ สรุปว่า degree ใดมีหลักฐาน underfit/overfit ในผลที่ได้ และค่าทำนายของแต่ละ degree ไวต่อการเปลี่ยนข้อมูลฝึกอย่างไร ระบุข้อจำกัดของการใช้เพียง 3 รอบ โดยไม่บังคับว่ารูปแบบผลต้องตรงทฤษฎีทุกครั้ง

P03 · Residual และการปรับปรุงโมเดล (6 คะแนน)

ต่อจาก P01 ตรวจ residual = y − ŷ บน validation 18 แถวของ Multiple model ด้วยกราฟ residual เทียบ fitted value และเทียบวันที่ แสดงอย่างน้อยหนึ่งประเด็นที่เห็นจริง และข้อจำกัดของการอ่านกราฟ เปรียบเทียบ candidate ที่กำหนด: (A) LinearRegression: temp_forecast_c, working_day; (B) LinearRegression: temp_forecast_c, temp_forecast_c², working_day; (C) และ (D) ใช้ features แบบ B แต่ใช้ StandardScaler → Ridge(alpha=0.1) และ Ridge(alpha=10) ตามลำดับ fit ทุกขั้นตอนด้วย train เดียวกับ P01 และเปรียบเทียบ validation RMSE เลือกด้วย validation RMSE (หากต่างกันต่ำกว่า 0.01 kWh ให้เลือกแบบที่ง่ายกว่า แล้วใช้ alpha ต่ำกว่าถ้าโครงสร้างเท่ากัน) อธิบาย trade-off และเหตุใดเพิ่ม feature/penalty แล้วไม่จำเป็นต้องดีขึ้น จากนั้น refit แบบที่เลือกบน development ทั้ง 90 แถว และประเมิน final test เพียงรอบรายงานสุดท้ายด้วย MAE, RMSE, R² ห้ามเลือกแบบใหม่จากผล test ส่งกราฟ ตารางผล โค้ด และข้อสรุป ไม่ต้องทำให้ผล test ดีที่สุดเพื่อรับคะแนน

P04 · ส่วนเสริม: ข้อมูลตามเวลาและ bootstrap (4 คะแนน)

ใช้ coefficient ของ temp_forecast_c ใน Multiple model แบบ A ของ P03 เป็นตัวอย่าง อธิบายหน่วยและความหมายเมื่อ working_day คงที่ โดยไม่สรุปเป็นเหตุและผล จาก development ทั้ง 90 วัน ให้ทดลอง ordinary pairs bootstrap (สุ่มคู่ X,y เป็นแถวพร้อมใส่คืน) 300 รอบ และ moving-block pairs bootstrap 300 รอบ โดยสุ่มบล็อก 7 วันที่ติดกันพร้อมใส่คืน ต่อบล็อกจนได้อย่างน้อย 90 แถวแล้วตัดเหลือ 90 แถว กำหนด seed 20260922 ทั้งสองวิธี รายงาน percentile 2.5 และ 97.5 ของ coefficient จากแต่ละวิธี อธิบายว่าแต่ละวิธีสมมติอะไรเกี่ยวกับการพึ่งพากันของข้อมูล และเหตุใดช่วงที่ได้ไม่ใช่ช่วงทำนายสำหรับการใช้ไฟฟ้าของวันใหม่ พร้อมยกตัวอย่าง feature วันในสัปดาห์หนึ่งแบบที่รู้ได้ ณ เวลาพยากรณ์ บล็อก 7 วันเป็นค่ากำหนดเพื่อการฝึก ไม่อ้างว่าเหมาะที่สุดหรือรับประกันช่วงความเชื่อมั่น 95%

ใช้ starter_gaussian_lab.ipynb สร้างข้อมูล y = sin(x) + ε โดย x ~ Uniform(0,10) และ ε มีการแจกแจงปกติที่ค่าเฉลี่ย 0 และส่วนเบี่ยงเบนมาตรฐาน 0.15 เป็นอิสระจาก x สร้าง train 50 จุดด้วย seed 41, validation 100 จุดด้วย seed 42 และ final test 100 จุดด้วย seed 43 โดยแต่ละชุดเริ่ม generator ของตนเอง 1) แสดง PolynomialFeatures(degree=3, include_bias=False) ของ x ใน train 3 จุดแรก และสร้าง Gaussian basis จำนวน N=12 ด้วย centers ห่างเท่ากันตั้งแต่ train_min ถึง train_max, width_factor=0.8, σ=width_factor×ระยะห่างของ centers รายงาน centers, σ และขนาด feature matrix ห้ามใช้ validation/test กำหนด centers หรือสเกล 2) fit Gaussian basis และ StandardScaler ด้วย train แล้วใช้ basis/สเกลชุดเดียวกันเปรียบเทียบ LinearRegression (OLS), Ridge(alpha=0.1) และ Lasso(alpha=0.001,max_iter=100000,tol=1e-6) โดยไม่จูนค่าอื่น รายงาน train และ validation RMSE ของทั้งสามแบบ 3) เลือก validation RMSE ต่ำสุด ถ้าต่างไม่เกิน 1e-6 ให้ใช้ลำดับ OLS, Ridge, Lasso เลือกตัวแรก เก็บโมเดลและ preprocessing ที่ฝึกบน train เดิม แล้วรายงาน final-test RMSE ของตัวที่เลือกเพียงแบบเดียว ไม่ refit หรือเลือกใหม่จาก test 4) อธิบายจากผลจริงว่า penalty เปลี่ยนผลอย่างไร เหตุใด alpha ตัวเลขเดียวกันข้าม Ridge/Lasso ไม่รับประกันแรง penalty เท่ากัน และเหตุใดการเปลี่ยน N พร้อมชนิด penalty ทำให้แยกสาเหตุของผลต่างได้ยาก ส่งโค้ด ตารางผล และกราฟ basis หรือ prediction พร้อมคำอธิบาย ข้อมูลเป็นการจำลองเพื่อฝึก ไม่ใช้สรุปผลระบบจริง
